# Runtime model

This site currently uses a static-prerender architecture with a small Express API boundary for contact-related endpoints.

## What runs at request time

- Known public routes are built by Angular prerender into `dist/hilando-fino/browser/**/index.html`.
- `server.ts` serves only known prerendered route files. Unknown routes return HTTP `404` with `noindex, nofollow` and a canonical URL of `/404`; they do not fall back to the home page.
- `/api/contact/csrf` issues short-lived, signed, one-time CSRF tokens bound to an HttpOnly SameSite cookie.
- `/api/contact` validates CSRF, rate limits, payload shape, spam controls, retention/contact feature flags, and provider behavior.
- `/__healthz` returns only `{ ok: true }` plus an optional HMAC identity for local spawned-server verification. It does not expose raw environment values, tokens, or process metadata.

## What does not run at request time

- The public route layer is static-prerendered; the Express server supplies the contact API, health check, and safe 404 response.
- The server does not use `AngularNodeAppEngine` to render arbitrary routes at request time.
- Unknown route handling is intentionally server-owned so crawlers and monitors receive a real `404`.

## Cache and security headers

- Static assets are served with immutable one-hour caching.
- HTML route responses and the safe 404 use `Cache-Control: no-store` while the site remains draft/noindex.
- Express disables `x-powered-by` and sets conservative content-type, frame, referrer, permissions, and opener-policy headers.

## Performance evidence

`npm run performance:smoke` is a self-contained navigation smoke probe: it builds with the pinned Node runtime, starts the built static-prerender server on a controlled free local port, waits for readiness, probes key routes, and cleans up. It does not claim Lighthouse or Core Web Vitals. `npm run lighthouse` runs real Lighthouse lab audits against the built server for home, local landing, service hub, and contact. Lab Lighthouse can measure LCP/CLS/TBT, but it does not prove INP; INP remains a launch/field-data gate after approved deployment traffic exists.

GitHub Pages deploys only the static browser/prerender artifact generated by `npm run build:pages`. Pages cannot run the Express `/api/contact` API, so the preview intentionally keeps contact disabled, draft/noindex, and without LocalBusiness/NAP publication.

## Node runtime determinism

The project pins Node `24.15.0` in `.nvmrc`, `.node-version`, `package.json#engines`, CI, and the lockfile-pinned `node@24.15.0` dev dependency. NPM scripts rely on the local `node_modules/.bin/node` resolution instead of `npx -p node@...`, so local/CI commands use the same supported runtime after `npm ci`.

## Fonts and deterministic performance

The production app does not load Google Fonts or other live font CDNs. Brand typography is approximated with local/system font stacks to keep Pages preview and performance gates deterministic. The original Google Font references remain only in brand/reference documents and the Stitch export.
